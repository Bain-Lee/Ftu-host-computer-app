# 重构分析与实现边界

## 结论

可以改用新框架。面向 Windows 10 / 11，选择 .NET 10 LTS + WPF，同时保持 x86。WPF 适合现有的数据表、树、参数编辑、桌面工具栏、录波和本地文件功能；跨平台目前没有明确收益，Jet 和厂商 DLL 也仍限定在 Windows。

本次已经完成一个覆盖全部编译窗口入口的 WPF 移植候选。**它还不是全面架构优化和全功能替换验收均已完成的最终基线。** 现有协议和业务控制器保留较多；为保持功能链路而建立了呈现适配层，尚未把所有业务逻辑从界面状态、全局对象和定时器中分离。

## 原工程的事实

统计只覆盖原 `.csproj` 显式包含的源码，不把同名旧副本算作正在使用的实现。

- 104 个非 Designer / Properties 编译文件，约 3.9 万行；54 个业务窗口。
- 单个 `C101Ptr` 约 3981 行，`C104Ptr` 约 3019 行，通信配置窗口约 2374 行。
- UI、规约、数据库和共享状态混用。业务类持有树节点 / 列表，窗体事件直接发送任务，规约通过窗口消息回传结果。
- 调用链中的任务号、地址、参数读 / 预置 / 固化 / 撤销和错误规约试验报文是业务契约，不适合为迁移而重新编号或简化。
- 旧代码中的 `BinaryFormatter` 深拷贝和 `Thread.Abort` 无法原样迁入现代 .NET。

以上属于源码事实；静态计数不是缺陷数量，也不是性能测量。此前用户已确认列表与窗口切换修复“明显改善”，不能据此推断所有通信路径和窗口都已完成性能验证。

## 框架比较

| 方向 | 适用性 | 本工程的主要代价 |
| --- | --- | --- |
| 现代 .NET WinForms | 运行时迁移最小，保留设计器与大量现有交互 | 界面仍是 WinForms，不能单独解决当前耦合与刷新问题 |
| .NET 10 + WPF | 适合 Windows 工具、大表格、树、绑定、原生绘制 | 需要移植界面语义与生命周期，逐步剥离业务控制器 |
| WinUI 3 | 可做新的 Windows 界面 | 重建控件与部署链的代价更高，对当前协议 / Jet 依赖没有直接收益 |
| Avalonia | 跨平台价值明确时值得考虑 | 现有数据库、原生 DLL 和厂商接口仍是 Windows 约束；本次没有跨平台需求 |

.NET 10 是 LTS，官方支持期至 2028-11-14。当前日期下不选择即将结束支持期的 .NET 8 / 9 作为新的长期基线。WPF 本身不会自动消除卡顿，UI 线程阻塞、全量刷新、对象生命周期和共享数据仍需独立处理。

## 当前实现

```text
App / RuntimePaths
  ├─ 选择工程目录、固定业务数据与原生库解析路径
  └─ WPF 视图与窗口生命周期
       ├─ 可通知的呈现模型、表格行与编辑状态
       ├─ 54 个移植控制器及对应视图描述
       └─ 原协议 / 模板 / 文件 / 转发表 / 加密与 SFTP 业务代码
```

当前视图使用 WPF 的 DataGrid、TreeView、文本与文档控件、原生窗口、几何曲线及位图绘图宿主。没有使用 WinForms 窗体嵌入，也没有通过启动旧 EXE 来补齐功能。程序集引用检查覆盖了这一点。

为控制通信回归风险，保留了原控制器的任务分派和应答推进。`Presentation.Form`、`MyListView` 等类型为这些既有调用提供 WPF 呈现模型；这种做法能移植完整入口，但也形成了适配层维护成本。不能把这一层描述成所有旧代码已经变为纯 MVVM。

已经落实的优化 / 兼容修复：

1. 列表使用原生虚拟化；批量装载只发一次集合重置通知，变化单元格才通知。修复了早期适配中旧空捕获掩盖的“只装载第一行”问题，真实模板检查断言完整行数。
2. 连接 / 断开转到后台，关闭等待正在进行的连接和历史读取；日志追加按后台优先级投递，避免接收线程等待日志排版。
3. 用进程内路由接收原消息号，不再把业务应答绑定到 Win32 HWND。关闭后的消息不再投递到已释放页面。
4. 用两种明确模型的复制函数替代 BinaryFormatter；为现代 BitConverter 重载明确旧字节 / 有符号字节的提升规则。
5. SQLite 改为 Microsoft.Data.Sqlite，使用一个连接、明确事务归属和释放；已有外部事务调用同步设置 Command.Transaction。修复旧代码的无名且未使用参数、文本单引号和转发表删除未纳入事务的问题；九类业务表保存重读及失败回滚通过。Access 连接及命令也补上释放。
6. 保留 Windows 实际 ANSI 代码页，避免现代 .NET 默认 UTF-8 改变已有文本规约。工程参数和导出默认目录按所选工程目录解析。
7. 加密接口抛错时不再返回成功，随机数调用异常时释放锁。相关检查使用模拟接口，没有调用真实加密机。
8. 用原生 WPF 替代 TeeChart 依赖，保留趋势绘制、缩放 / 平移、录波绘图与游标逻辑；监视页支持关闭、独立窗口和返回停靠。
9. 修复定时器释放后被排队的绑定更新重新启动、动态控件重复挂载、单选和双击编辑路由、模态确认不关闭等实际离线检查发现的问题。
10. 新项目保持告警级别 4、告警视为错误，没有通过告警抑制或删掉业务入口来换取编译通过。

## 仍未完成的工作

### 架构与代码质量

- `CGlobal`、静态遥控 / 试验状态、共享列表和部分计时状态仍存在。
- 模板 / 参数模型仍包含呈现行为；大量旧业务事件尚未提取为独立服务与命令。
- 一次性迁移保留了较多原编码风格、重复解析和空捕获分支；并未声称已经逐个审查和修复所有历史错误。
- 趋势与停靠交互已由 WPF 实现，但旧 ActiveX / 停靠库的每个隐含交互选项尚未逐项人工等价验证。

这些工作不能用“零编译告警”替代，也不应为了外观整洁改动未验证的报文算法。下一步应在现有报文对照与 UI 检查保护下，按参数事务、文件传输、连接管理等模块逐个移除全局依赖。

### 设备与运行验收

- 101 / 104 的真实串口、TCP 客户端和监听模式，包括连接丢失与重连。
- 遥控选择 / 执行 / 撤销的成功、拒绝、超时和设备侧状态。
- 参数读取 / 预置 / 固化 / 撤销、分包和工程参数保存重开。
- 转发表 / 厂站 / 终端 / 主站编辑、SQLite 保存重开和实际下发。
- 历史 / 录波 / 文件上下行、断点 / 错误应答、普通升级及 FTU 快速升级。
- 厂商 1.1 / 1.2 加密库、证书、密钥操作和加密报文。
- 新 SSH.NET 与现场 SFTP 服务的协商、目录权限、上传 / 下载 / 删除。

这些条目尚未实测；112 组固定报文一致不证明完整规约符合性，也不证明现场升级或固化成功。尚未获得真实终端操作的授权范围，因此没有执行上述设备操作。
